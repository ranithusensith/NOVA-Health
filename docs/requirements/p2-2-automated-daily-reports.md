# P2-2 Automated Daily Health Reports

The September 23, 2026 NOVA Health proposal lists automated daily health reports and analytics. It calls for reports that combine food, hydration, physical activity, and other health records. NOVA now generates deterministic daily snapshots of these records for opted-in accounts. It uses account goals, confirms the date and source for eligible imports, and reports missing values as unknown. Long-term analytics, clinical interpretations, and proactive health alerts are beyond this implementation.

## Scheduling and privacy

- Enable generation in **Profile → Automatic daily reports** or in the live Daily report screen. The schedule starts with the local date on which the user opted in. Each completed date becomes eligible after 8:00 a.m. the next day in the account's saved time zone. NOVA uses the local midnight boundaries of that date, including offset changes. **Use device zone** updates future dates explicitly and preserves the original dates and zones of saved reports.
- Supabase Cron runs the generator every five minutes. The worker processes up to 100 due accounts per run and at most one report per account per run. It retries failed accounts after 15 minutes and catches up at most seven completed dates after a disruption. Database locks and a unique account/date key protect concurrent and repeated runs. The schedule is independent of phone restarts, connectivity and signed-in sessions.
- Snapshots retain account-scoped numeric observations and source labels for 30 days. They include water and sleep goals, recorded water and sleep, eligible imported steps or sleep, confirmed meal counts and calories, scheduled dose confirmations, and symptom onset counts. Snapshots omit free-text notes, medication names, pending scans, unmatched or premature platform imports, and ambiguous measurements. Recent edits or late imports can appear in the live report without rewriting an already generated snapshot.
- Optional device notices are checked on signed-in app launch, resume, and every five minutes in the foreground. The device shows a generic update only after the server atomically claims the previous completed date's existing snapshot. This prevents duplicate notices across devices and restarts. Background push delivery is outside this feature. A claim followed by a lost response or a native delivery failure can suppress the alert. The report remains available in the archive.
- Reports are generated inside the database and presented by the deterministic NOVA API. No external AI, outsourced notification service, or stored mobile credential is involved. RLS restricts report reads to their owners. Sign-out cancels local delivery and drops open report screens. Generation continues for the opted-in account until the user turns it off, which deletes its saved snapshots.

## Scheduler setup

1. Apply migration 016 after 015 in the approved environment. New accounts start with generation off.
2. Enable Supabase Cron, then run [setup_daily_report_cron.sql](../../backend/changes/setup_daily_report_cron.sql) as the database owner role used for the NOVA migrations. This role must be able to run Cron jobs and read the existing source tables. The report generator has no app-role execution grant. Verify the job owner, frequency, and recent runs before enabling the app setting for users. [Supabase Cron quickstart](https://supabase.com/docs/guides/cron/quickstart)
3. On a disposable environment, verify a synthetic opt-in, an elapsed due time, and the generated snapshot. The runner returns aggregate success or failure counts and emits a bounded warning on per-account failures. Test job recovery, backlog throughput, and retention against the expected account count.

The isolated SQL regression runs the scheduler function at synthetic times and checks time-zone boundaries, DST, opt-in, retry, retention, ownership and deduplication. It does not require a hosted Cron extension. Signed-device tests should confirm the native time-zone value, permission handling, generic notification previews, and sign-out behavior.
