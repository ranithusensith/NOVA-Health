# External AI privacy

NOVA uses Google Gemini to select assistant tools and create scan drafts when the provider has been approved and the account opts in to the current disclosure. NOVA assembles the visible assistant reply from saved observations and fixed safety rules. The API checks consent at entry and again before each provider request, including a retry. To withdraw, use **Profile → Privacy and consent**. Withdrawal blocks future requests after the server records it. A call already in flight can complete.

## Data sent to Gemini

- A reviewed assistant question and, if selected, up to four earlier user questions from the same open conversation. The default sends only the current question. The user may select record categories for that reply. The assistant only has tools for those categories, and their outbound projections omit account IDs, exact log timestamps, cycle start dates, medication schedules, and lab report dates. Local medication safety rules add their full notes only to NOVA’s response.
- Reviewed clinical text from a prescription or lab report. NOVA’s server runs Tesseract and proposes text with common identifier fields removed. The user can remove residual identifiers, correct errors or enter clinical text manually. The API redacts the reviewed text again. No original medical photo or medical photo metadata goes to Gemini.
- A food photo explicitly reviewed by the user. The backend renders the pixels into a new bounded JPEG. NOVA also uses local OCR to reject recognizable identifying text. Faces, documents, and identifiers missed by OCR can remain visible in the pixels. The review asks the user to cancel if any are visible.
- Red-flag chat handling, symptom draft checks, daily reports, medication safety review and medication confirmation run inside NOVA. Manual entries and edits require no Gemini consent.

When tracking logs are selected, the assistant provider can receive a bounded symptom count and recorded severity/status values. NOVA displays the account's documented symptom labels and local onset dates from its own evidence. Stored symptom names, notes and onset dates stay out of the tool payload to Gemini. Text the user types directly into a reviewed chat question follows the normal chat disclosure.

Weather uses an explicitly selected city. NOVA sends the entered city search and the selected city's public ID or approximate coordinates to Open-Meteo. The weather provider receives no NOVA account ID, session token or health records. The app keeps the selection in memory for the signed-in session. In a reviewed assistant reply, an unchecked-by-default option allows NOVA to display current weather evidence. That option does not add the city or weather fields to the Gemini request. User-typed text in the question follows the existing chat disclosure.

Outdoor planning notices use a separate opt-in for a chosen city on that device. NOVA stores the chosen city and latest claimed city date in account-scoped device preferences. While NOVA is open and that account is signed in, the enabled notice can check the public city forecast. Notification previews use generic text, and the feature reads no health records or external AI.

Wearable steps and sleep imports run only when selected on the phone. NOVA stores account-owned daily totals and the calendar boundaries needed to place them correctly. A reviewed Assistant reply can separately opt in to imported steps and sleep. Gemini receives only the selected bounded totals, with no exact dates, times, source identifiers or raw health-platform records. Local reports require no AI consent.

Automatic daily reports require a separate account opt-in. A database job produces owner-readable summaries within NOVA and keeps them for 30 days. It uses no external AI or mobile session token. Reports can generate while the user is signed out. Turning generation off removes saved automatic reports. Optional device notices contain only generic text and are checked while that account is signed in and NOVA is open. The app stores no report bodies in its preferences.

**Compare records** is a separate, on-demand Assistant action. Both sources must be approved for each comparison. NOVA uses the signed-in account's database role to read the approved categories and creates the reply on its backend. The request, observations, and reply stay out of external AI and weather services. A dose-and-symptom comparison applies the existing recent symptom safety check before reading dose logs. Comparison results live in assistant screen memory and are excluded from earlier-question sharing.

## Storage and deployment

- Apply the [ordered Supabase migrations](database-setup.md) as an authorized migration owner. Migration `004` creates the account-scoped table for the disclosure version and consent timestamp. Users begin opted out when the table is first created. Deploy the matching mobile and API versions. Clients using the previous scan or assistant request format must update.
- Deploy with Pillow and Tesseract plus the English OCR model. The backend container installs these. Set an HTTPS API URL for the mobile release. Keep request and response capture disabled across the reverse proxy, application monitoring, tracing and error reporting. Configure a suitably protected temporary filesystem for multipart uploads and avoid disk backups of it. FastAPI may spool incoming uploads temporarily, and the request closes the file. The app does not persist original scan photos to Supabase. The device image picker may create temporary local copies, and the user’s original remains on the device.
- Keep `AI_PRIVACY_PROVIDER_APPROVAL` unset until the organization approves the intended uses and verifies the Google account, applicable terms, paid project and model, data-processing terms, provider data-use and retention settings, monitoring, access controls and transfer locations. After approval, an operator may set it to `gemini-reviewed-paid` with the approved project key. This variable is an operator attestation. NOVA cannot verify billing, terms, or provider settings through the inference API. Do not enable the integration on free quota for sensitive data or for uses prohibited by the applicable service terms.
- New assistant messages and answers stay in mobile screen memory, capped at 100 messages. NOVA has no server-side transcript for new conversations. **New conversation** clears the transcript and unsent draft, and any later reply from the previous conversation is ignored. Changing accounts discards the previous account's screens and dialogs. Withdrawing sharing from the app also clears the current assistant conversation after the server confirms the change. Confirmed scan results remain in the corresponding health-record tables and use those records’ own controls.
- **Delete older NOVA chats** removes the signed-in account’s legacy rows from the active database and reports whether deletion was verified. This works independently of Gemini consent. Migration `010` adds a database-owner maintenance function for 30-day retention. Configure and verify a daily run from a trusted database job. See the [retention runbook](database-setup.md#h11-legacy-chat-retention).
- Active-database deletion does not immediately erase backup snapshots, point-in-time recovery logs, exports, replicas with their own retention, or older application and infrastructure logs. Inventory existing copies and expire them according to approved policy. After a restore, reapply documented account deletions and run the legacy retention job before reopening access. Use a protected deletion record with the minimum necessary identifiers if account deletions must be replayed.
- NOVA cannot delete copies held by Google or a communications provider, or remove disclosures already sent. Use the approved provider's administrative deletion and retention process where available. Keep request bodies, response bodies, headers, raw exception details and parameterized URLs out of reverse-proxy logs, observability tools, database diagnostics and crash reporting. OS diagnostics, keyboards and device screenshots or task previews are outside the application's logging controls.
- Water and sleep tracking goals are stored on the signed-in profile. Set any previous device goals again from that account. Daily calculation offsets stay within NOVA. Appearance is a device preference.
- Redaction is best-effort. Unlabeled names, unusual identifier formats and combinations of clinical facts can remain identifying. The OCR engine can misread handwriting or non-English text. Keep confirmation of the original prescription or lab record in the workflow.
